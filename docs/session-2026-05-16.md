# M2.1 — NER scanner, entity aliases, output-side name scan

## Context

M1.6 (2026-05-15) completó la detección regex de instrumentos financieros y
hardening edge-cases. El bug que abrió M2.1: al escribir "hola me llamo miguel"
(minúscula, sin contexto de empresa), el modelo respondía "Te llamas Miguel" —
el nombre llegaba al modelo y volvía al usuario sin redactar.

## Decision / Outcome

### 1. `deep_devops/router/entity_aliases.py` — pseudonimización de entidades

Módulo nuevo. Aplica sustituciones organización→alias antes de que el texto
llegue a ningún tier. Reversible: `AliasContext.restore()` reconstruye los
nombres originales en la respuesta del modelo. Orden longest-match para evitar
solapamientos parciales.

Alias configurados (sin documentar la razón de negocio de cada uno):
- mapfre tech → aseguradora M tech
- mapfre → aseguradora M
- el corte inglés → grupo retailer
- acciona → conglomerado infraestructura
- ecovidrio → gestión de residuos

### 2. `deep_devops/data/names.py` — wordlists INE + internacional + diminutivos

Set de nombres de pila y apellidos de: España (INE 2023), Europa (DE/FR/IT/PT/
PL/NL), Suiza (BFS), Latinoamérica (MX/CO/AR/CL/PE), USA/Canadá (SSA) y UK
(ONS). Añadido set `DIMINUTIVOS` (dani, paco, javi, adri, alex, fer, guille,
cris, manu, rafa, rodri, mari, bea, xavi y otros comunes).

### 3. `deep_devops/router/ner_scanner.py` — NER con spaCy + wordlist

**Pipeline de normalización** (`_norm`): lowercase + strip diacríticos vía
`unicodedata.NFD→ASCII`. Hace la detección resistente a case, tildes y errores
tipográficos por acento (Angel == Ángel, garcia == García, MIGUEL == miguel).

**Detección de nombres compuestos** (`_merge_compound_names`): tras detectar
entidades individuales, mergea cadenas adyacentes separadas por ≤ 3 chars
(espacio, guión, variantes de guión, sin límite de tokens). Cubre:
- Espacio: "Miguel Angel", "Maria Jose Garcia"
- Guión: "Juan-Carlos"
- Guión con espacios: "Juan - Carlos", "Juan- Carlos", "Juan -Carlos"

**Gate de contexto**: en la ruta de entrada (`require_context=True`) la
detección wordlist solo se activa con palabras clave de referencia personal
("me llamo", "mi colega", "my name is", …). En el output scan se usa
`require_context=False` para capturar cualquier nombre que el modelo echo.

**spaCy complementa wordlist**: si `es_core_news_sm` está instalado se usa para
PER; el wordlist cubre lo que spaCy puede perder en minúsculas o diminutivos.

### 4. Output-side NER (`_scan_output` en `model.py`)

`_scan_output` ahora ejecuta tanto `pii_scanner.scan()` (regex) como
`ner_scanner.scan(require_context=False)`. Si el modelo escribe "Te llamas
Miguel" aunque el input no fuera redactado, el output scan lo detecta y lo
sustituye por `[OUTPUT_REDACTED_NOMBRE_PROPIO]`.

### 5. Integración en `_route()`

Orden de operaciones:
1. `entity_aliases.apply(user_text)` — org names → sector aliases
2. `pii_scanner.scan(aliased_text)` — regex PII
3. `ner_scanner.scan(aliased_text)` — nombres personales
4. `_merge_scan_results()` — combina, PII tiene prioridad en overlaps
5. `redact()` → `{/TIPO_N/}` placeholders
6. Output: `_apply_output_scan()` + `_apply_alias_restore()`

Traza ampliada: `alias_applied`, `alias_count`, `ner_entity_types`.

## Rationale

- Cap 10 p.451-452: input guardrails en la capa de gateway, antes de
  cualquier llamada al modelo. Los alias son un guardrail de pre-procesamiento
  que complementa el redactor de PII.
- Cap 3 p.144: señales deterministas, sin LLM-judge. El NER con spaCy y el
  wordlist normalizado son O(n) y sincrónicos — conformes con el diseño de
  hot-path.
- design.md §4.2: fail-closed. Si `ner_scanner.scan()` lanza excepción, la
  excepción se propaga al bloque try/except de `_route()` y la llamada se
  aborta (ya cubierto por QA-D05).
