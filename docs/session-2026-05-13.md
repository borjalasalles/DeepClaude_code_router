# Session 2026-05-13 — Initial design and provider strategy

## Context

First working session for `deep-devops`. The user described an enterprise project they had seen (Snowflake + Cortex + Streamlit + Claude-via-API) and wanted an open-source equivalent. Key adjustments to that baseline:

- Use `langchain-ai/deepagents` (which already ships a CLI + TUI) instead of building one from scratch.
- Default to DeepSeek for cost; reserve Claude for the hard cases.
- No local LLMs.
- EU-hosted inference preferred (latency + GDPR), ideally cheaper than Groq.
- Will run locally first, share via GitHub with colleagues if it works.

## Decisions taken in this session

### 1. Build on `deepagents` upstream CLI (not a fresh CLI/TUI)

Confirmed via web fetch: `langchain-ai/deepagents` ships a CLI installed by `curl -LsSf https://langch.in/gh-da-cli | bash` with a rich TUI ("similar to Claude Code or Cursor"). Saves the entire UI layer.

### 2. Three-tier model routing (v0.2, replaces v0.1's two-tier)

Initial proposal (v0.1) was Nebius (EU) + Anthropic escalation. User noted that the cheapest option — DeepSeek native API at $0.14/$0.28 per M tokens for V4 Flash — could still be used for **non-confidential / non-PII / non-company-internal** queries (e.g., questions about public schemas, open-source library docs, generic SQL/algorithm questions). Revised to three tiers, picked per query class:

1. DeepSeek native (China) — public-only.
2. Nebius (Amsterdam, EU) — internal default.
3. Anthropic — confidential + escalation.

Gated by a **whitelist publicness classifier** (a query must affirmatively look public) and an env **kill-switch** (`DEEP_DEVOPS_DISABLE_PUBLIC_TIER=1`) that collapses tier 1 → tier 2.

### 3. Cloud provider research (justification)

Verified against the user's three factors (price, privacy, latency from Spain) and the explicit requirement "no sea el mas caro" + cheaper than Azure Foundry / AWS Bedrock:

- **AWS Bedrock DeepSeek-R1:** $1.35 / $5.40 per M tokens (confirmed AWS docs).
- **Azure AI Foundry DeepSeek:** same hyperscaler tier; exact price to verify at signup.
- **Nebius Token Factory (Amsterdam):** specialist EU tier, ~3–5× cheaper than hyperscalers, serves DeepSeek V4 today, GDPR. **Chosen for tier 2.**
- **Scaleway Generative APIs:** would have lowest latency from Spain (Paris), 1M free tokens to start, but V4 not yet in catalogue. **M2 swap candidate.**
- **EUrouter:** EU gateway, adds margin → not the cheapest.
- **OVH AI Endpoints:** V4 not confirmed.
- **DeepSeek native (China):** cheapest globally at $0.14/$0.28; disqualified by privacy rule for internal data but **reclaimed as tier 1** for queries that have no privacy requirement.

### 4. Book as ground truth

Read chapters 3 / 4 / 9 / 10 of *AI Engineering* (Chip Huyen) and aligned design with cited recommendations. ## Rationale (cite book)

- Provider choice as a **per-query** filter rather than a global one is the natural extension of Cap 4 p.179-180 (hard vs soft attributes). The privacy hard attribute attaches to **the data in the query**, not to the project as a whole.
- Refusing LLM-judge for the publicness classifier follows Cap 10 p.457 ("routers should be fast and cheap") and Cap 3 p.144 (LLM-judge unreliable). For a one-way error like a privacy leak, determinism matters more than nuance.
- The PII reverse-map redaction enables sending **the non-confidential remainder** to a lower tier rather than wholesale escalation (Cap 10 Fig 10-3, p.453). Cost-aware safety.
- Implicit feedback from the TUI (user edits, regenerations, Ctrl-C) feeds the skill factory as (losing, winning) pairs (Cap 10 p.478). Integrated > standalone (Cap 10 p.487) — our advantage over chatbots.
